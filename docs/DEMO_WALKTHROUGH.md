# VillageCoverage V5.2 RC1 데모 walkthrough

**길이:** 5–7분. **주요 이야기:** 요청이 적은 마을 → 수요가 없다고 단정하지 않음 → 더 조사할 곳을 찾음 → 네 가지 공급안을 비교 → 비용과 미충족의 trade-off 확인 → 공급자 거절 후 재계획 → 담당자 검토·승인.

## 시연 전 준비

1. Python `>=3.12,<3.15`, Node.js `>=20.9`, `uv`, `npm`을 확인합니다.
2. `uv sync --all-groups`, `cd frontend && npm ci`를 실행합니다.
3. `scripts/start_demo.sh`로 시작합니다. 매 실행은 새 임시 앱 DB를 사용합니다. 기존 데모 운영 기록은 가져오지 않으며, 별도 route cache는 지우지 않습니다.
4. 시나리오 일정 계산을 보여주려면 현재 지역의 완전한 directed Kakao Mobility route cache가 필요합니다. 체크인된 fixture만으로는 이 cache를 만들지 않습니다. cache가 없으면 계획 계산은 실패 안내를 보여주므로, 시연 전에 승인된 local cache를 준비하고 route 출처·기준을 `LOCAL CACHE`로 설명합니다. 키나 개인 DB를 제출 자료·스크린샷에 넣지 않습니다.
5. map JavaScript key는 선택 사항입니다. 키가 없으면 좌표 대체 화면으로 계속 진행합니다. 시작 시 외부 데이터 API를 호출하지 않습니다.

## 오프라인·실패 시

- 앱 시작과 checked-in demo fixture 열기는 외부 API key 없이 진행합니다.
- 수집 smoke/API refresh는 opt-in 명령이며, 시작 스크립트는 실행하지 않습니다.
- cache가 있는 공개 데이터 adapter는 성공 후 live fetch 실패 시 `CACHE_FALLBACK`과 기준일을 표시합니다. cache가 없으면 실패를 표시하고 임의 값을 만들지 않습니다.
- route cache가 불완전하면 해당 계획은 계산되지 않습니다. 직선거리·기본값으로 대체하지 말고 데이터 품질/오류 안내를 보여줍니다.
- Kakao 지도 SDK를 사용할 수 없을 때 좌표 대체 화면을 확인합니다.
- 빈 화면·500 원문이 보이면 해당 흐름은 중단하고 오류 메시지와 API status를 기록합니다. 오류 상태를 정상 시연처럼 말하지 않습니다.

## 재시작으로 demo 상태 초기화

UI의 “전체 초기화” 버튼은 없습니다. `scripts/start_demo.sh`를 종료하고 다시 실행하면 새 임시 app DB를 사용하므로 plan·승인·feedback 상태가 초기화됩니다. 앱 DB는 스크립트가 삭제하지 않습니다. 로컬 route cache는 별도 경로에 그대로 남으며 사용자 DB를 자동 삭제하지 않습니다.
