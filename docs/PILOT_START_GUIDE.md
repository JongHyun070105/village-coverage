# VillageCoverage 파일럿 시작 안내

이 prototype은 지자체 담당자의 검토를 돕는 의사결정 지원 도구입니다. 계획·공급자 연결은 자동 행정결정이나 자동 계약이 아닙니다. 공급 참여는 당사자가 opt-in으로 확인해야 합니다.

## 파일럿 시작 순서

1. **지역 선정**: 기초자료를 제공할 행정 담당자와 pilot 권역, 법정동 코드, 기준일을 정합니다. 한 번에 모든 지역을 열기보다 자료를 확인할 수 있는 작은 권역부터 시작합니다.
2. **담당자 지정**: 지역자료, 주민조사, 공급자 연락, 서비스 수행기록, 개인정보 검토 담당을 정합니다. 연락처 원문은 이 시스템에 업로드하지 않습니다.
3. **필수 데이터 확인**: [파일럿 데이터 체크리스트](PILOT_DATA_CHECKLIST.md)에서 법정동 코드·인구 기준일·초기 서비스 범위·담당자 승인 조건을 확인합니다.
4. **선택자료 수집**: 공공인구·시설 자료, 주민조사, 지역 수요관측, 공급자 자발 응답, 단가, 기존 제공 이력, 수행로그를 확보합니다. 항목마다 출처·기준일·수집방법을 기록합니다.
5. **공급자 확인**: [공급자 데이터 안내](PROVIDER_DATA_GUIDE.md)에 따라 공식 디렉터리 등록, 서비스 매핑, 가용성·수용량·가격 확인을 분리합니다. 조직 존재만으로 참여 가능성을 판단하지 않습니다.
6. **기초조사**: 표준 CSV를 미리보기하고 행별 오류·경고를 확인합니다. 조사 메모에 이름·전화번호·상세 주소·민감정보를 넣지 않습니다.
7. **첫 계획**: 근거·누락·모의값 표시를 확인하고 Efficiency, Balanced, Underserved-first, Minimum 정책을 비교합니다. 예산과 서비스 범위는 담당자가 선택합니다. 현재 버전의 파일럿 CSV는 검토·확정 workspace에 저장되지만 optimizer 입력에는 연결되지 않습니다. 따라서 지금 생성되는 계획은 데모 시뮬레이션이며 실제 업로드 자료를 반영한 pilot 계획으로 사용할 수 없습니다.
8. **검토·승인**: 미충족 마을, zero-service, 비용 구성, 공급자 후보 조건과 대체안을 확인합니다. 담당자 승인 전에는 계획을 확정된 행정결정으로 취급하지 않습니다.
9. **실제 수행**: 공급자와 일정·조건을 별도로 확인합니다. 시스템의 거리·서비스 유형 후보 표시는 실제 참여 약속이 아닙니다.
10. **수행로그 회수**: 완료·취소·불참·미수행, 실제 회차, 날짜, 미충족 요청을 비식별 상태로 회수하고 source type을 `SERVICE_EXECUTION_LOG`로 표시합니다.
11. **보정 검토**: [검증 계획](PILOT_VALIDATION_PLAN.md)의 기간·표본·출처 다양성·중복·신선도·실제 수행 조건을 모두 확인합니다. 행 개수만으로 보정 상태를 올리지 않습니다.

## 현재 준비도 표시

이 checkout은 field-pilot prototype입니다. 이 저장소의 합성 운영 데이터는 데모에만 해당하며, 실제 지역 longitudinal demand, 공급자 가용성·수용량·가격, 기관 인증, 현장 파일럿 실적은 확보되지 않았습니다. 해당 자료가 없으면 `UNKNOWN`, `MISSING`, `SIMULATED` 상태를 유지하십시오.

## 현재 기능 경계

파일럿 자료 import는 업로드·미리보기·검증·담당자 확정·출처 기록까지 수행합니다. 확정된 `pilot_import_records`는 기존 공급계획 optimizer, provider assignment, Decision Memo 계산으로 전달되지 않습니다. 파일럿 데이터를 사용한 계획 생성·승인·실행 성과 연결은 아직 구현되지 않았으므로, 실제 업무 결정에 이 입력을 반영하지 마십시오. 이 통합과 기관 사용자 인증이 완료되기 전에는 이 빌드를 실제 현장 파일럿 계획에 투입할 수 없습니다.
