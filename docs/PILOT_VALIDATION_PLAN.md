# 파일럿 검증 계획

이 문서는 측정 방법과 목표만 정의합니다. 현장 결과 데이터가 아직 없으므로 실제 성과 값은 기입하지 않습니다.

현재 파일럿 CSV workspace는 기존 optimizer와 분리되어 있습니다. 아래 비교와 KPI 수집은 운영 설계이며 이 빌드에서 업로드 행을 기준으로 계획·실적을 산출하지 않습니다. 실제 현장 비교를 시작하기 전에 파일럿 입력을 계획 snapshot에 결합하는 구현과 기관 승인을 완료해야 합니다.

## 비교 설계

같은 지역, 같은 observation window, 같은 서비스 범위, 같은 예산·공급 가능 정보로 비교합니다.

1. 기존 행정계획/수작업 계획을 기준선으로 보존합니다.
2. request-history-only 기준선은 기존 요청 이력만 사용하는 별도 계획으로 산출합니다.
3. VillageCoverage 시나리오는 담당자가 정책 목적을 선택하고 같은 승인된 자료 snapshot과 정책 설정을 사용합니다.
4. 가능한 경우 담당자 검토자가 계획 명칭을 가린 상태로 비교합니다. 현장 수행 결과를 확보하기 전에는 효율성 개선을 주장하지 않습니다.
5. 같은 snapshot/config/seed 및 optimizer version으로 재실행해 기존 승인 결과와 비용이 유지되는지 확인합니다.

## 사전 정의 KPI

| KPI | 측정 정의 | 보고 분모·근거 |
|---|---|---|
| 서비스 0 마을 수 | 기간 내 실제 계획 또는 수행이 0회인 서비스 권역 수 | 전체 eligible 마을 수, 서비스 scope |
| coverage | 승인된 서비스 대상으로 실제 완료가 확인된 마을 비율 | eligible 마을·요청 구분, 실행로그 |
| service rounds | 완료된 서비스 회차 합계 | 날짜·서비스·중복 제거 기준 |
| unmet requests | 기간 종료 시 미완료 또는 명시적 미충족 요청 | 조사/요청 원본과 상태 이력 |
| wait days | 접수부터 완료/종결까지의 경과일 | 요청 ID 익명화 및 기준일 |
| replan frequency | 공급자 불참/상황 변화에 따른 재계획 횟수 | 계획 버전·변경 이유 |
| provider decline | 초청 중 거절/불가 응답 비율 | 초청 건수, opt-in 기록 |
| cost difference | 같은 범위의 계획 비용과 실지출 차이 | 단가·이동·시간·자재·지원금 내역 |
| additional funding | 기존 재원 차감 후 필요한 추가예산 | 구성항목별 추적, 통화·기준일 |
| resident feedback count | 중복 제거된 의견·정정 건수 | 수집 채널, 비식별 처리 |
| survey completeness | 수집 완료된 적격 표본 / 계획 표본 | 서비스·기간·마을별 표본 정의 |

각 KPI는 실제 관측과 scenario estimate를 분리합니다. 목표값을 실제 측정값처럼 표기하지 않습니다.

## 보정 승격 조건 (초기 운영 규칙)

- `UNCALIBRATED`: 실측 근거 없음, 합성값만 있음, 또는 최소 조건 미충족.
- `LIMITED_SAMPLE`: 비합성 local survey/observation은 있으나 아래 지역·기간·표본·출처·신선도 조건 중 하나 이상 미충족.
- `LOCAL_CALIBRATED`: 서비스별 비합성 unique observation 30건 이상, 조사/관측 기간 90일 이상, 서로 다른 source type 2개 이상, 적격 모집단 분모 존재, 가장 최근 근거 180일 이내, 미해결 중복·충돌 0건을 충족하고 담당자가 검토.
- `LOCAL_VALIDATED_OPERATIONAL`: `LOCAL_CALIBRATED` 조건과 함께 완료된 실제 수행로그 30건 이상, 최소 90일 운영기간, 최근 180일 이내 실제 공급자 availability·capacity·단가, opt-in/decline/unavailable 참여결정 기록을 확보하고 현장 책임자가 확인.

위 수치는 시작 전 정한 최소 gate이며, 충분성에 대한 통계적 보증이 아닙니다. 중복행은 fingerprint로 제거하며 행 수만으로 승격하지 않습니다. 자격·지역 범위·모집단 정의는 기관이 먼저 승인해야 합니다. 미해결 충돌이 없음을 현재 prototype은 완전하게 자동 보증하지 않으므로 담당자 검토를 필수로 둡니다.

## 기록할 위험·중단 조건

- source/schema drift, stale cache, 노선 누락, 공급자 불참, 조사 지연, 가격 누락, 서비스 매핑 미확정, 표본 편향, 결측을 각각 기록합니다.
- 서비스 안전 scope 위반, 재사용 허가 불명확, 개인정보 노출, 승인 snapshot 불일치 시 해당 자료 또는 계획 사용을 중지합니다.
- 기존 행정절차 및 담당자 승인 없이 자동 배정·계약·자격 판정을 수행하지 않습니다.
