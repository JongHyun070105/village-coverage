# VillageCoverage V5.1 Solver Acceptance Audit

**Decision: PASS — V5.1 solver scalability acceptance is complete.** The selected prototype default path is `BASELINE_DECOMPOSED` (benchmark key `S1_V5_BASELINE`). Geographic decomposition and rolling horizon are implemented and safety-tested, then rejected for default adoption because current benchmarks show worse quality and/or runtime. That adoption decision is not an implementation failure or a production-readiness claim.

Audit target: branch `v5-1-solver-completion`, HEAD `d69e5d87e8deae527a84572b4910e523c6a45195`. Solver and strategy benchmarks use deterministic synthetic inputs and local synthetic road edges; they do not establish field performance.

## Performance record

The committed three-repeat profile recorded V5 → V5.1 medians of 1.54 → 1.42, 6.58 → 2.65, 8.05 → 4.82, 10.72 → 5.07, and 16.36 → 5.37 seconds for 16/30/50/100/200 areas. A same-seed, three-repeat replay on the audited HEAD measured 1.53/2.92/5.20/5.58/6.71 seconds. The exact medians vary, but every latency threshold passes and four scale sizes still improve meaningfully against the V5 profile.

The measured improvement came from removing repeated minimum-budget diagnostics from the ordinary scheduling path and reusing candidate/route preprocessing. The 200-area time-indexed schedule remains the dominant cost. Geographic clustering was not the speedup.

## Final decision and limits

V5.1 implementation and solver-safety acceptance is **PASS**. `BASELINE_DECOMPOSED` is selected; geographic and rolling are retained as implemented experimental strategies and rejected for default use after benchmark. This decision does not claim global optimality, 100% solver resolution, real-road latency, or field service quality. Six stress outcomes stay `UNKNOWN`; warm-start benefit is small; heuristic pruning is not selected. The machine-readable record is `artifacts/v5_1_acceptance_audit.json`.
